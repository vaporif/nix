**Sizing software work.** Size by what the repo shows, not by how
familiar the kind of work feels. It is a project with a written design if
any of these is true:

- it adds a new unit
- it changes an interface another unit depends on
- it touches more than one existing unit

Otherwise it may be a small change. Still unsure? Take the heavier size.
Sizes only go up mid-task, never down.

Two thoughts mean you are under-sizing:

- "I'll call it small and skip the design." Reaching for the lighter size
  to save work is the doubt; take the heavier one.
- "I know this kind of app, so it's small." Familiarity isn't size. If
  there's no existing code here to change, it adds units, so it's a
  project.
